# P0 · проверка отбора черновиков в пакет (#245)

Сценарий готовит личную контрольную точку [#245](https://github.com/MOX-Studio/MOX-ADV/issues/245) для Feature [#242](https://github.com/MOX-Studio/MOX-ADV/issues/242). Он реализует и проверяет задачи #287 и #288, но не записывает решение владельца.

## Граница безопасности

- Отбор, восстановление, порядок и package review работают только с неизменяемыми Campaign Draft и сохранёнными read-only доказательствами.
- Подтверждение пакета, `dispatch_package`, provider mutations, выдача live authority, показы и расходы в этой проверке запрещены.
- Личные кабинеты Яндекса не используются.
- Управляемый браузерный сценарий является явно обозначенной фикстурой и не подменяет независимый read-only снимок реального бизнеса.

## Воспроизведение

Из `dashboard/`:

```bash
npm run test:package-selection
npm run test:contract
npm run test:e2e
```

Проверяемые артефакты:

- `tests/evidence/p0-viable-campaign-real-business.json` — независимые текущие read-only доказательства, принятые на предыдущей функции;
- `tests/evidence/p0-package-selection-acceptance.json` — машиночитаемая приёмка #242;
- `tests/e2e/test_p0_production_candidate.py` — управляемый UI-сценарий 1920×1080: исключить → вернуть → изменить порядок → открыть точный пакет;
- `tests/p0-application-contract.test.mjs` — CAS, BLOCKED/stale rejection, package invalidation и normalization-only preservation.

Независимый пакет не выдумывает отсутствующие конкурентные и freshness-доказательства: его preflight честно показывает `7/9 · BLOCKED`. Отдельный управляемый браузерный сценарий проверяет полностью подготовленный `9/9` пакет. Это разделение сохраняет происхождение доказательств и не превращает фикстуру в утверждение о текущей готовности реального рекламного аккаунта.

## Что лично проверить при 1920×1080

Откройте локальный Dashboard только через UI.

1. На этапе «Кампании» укажите `0` для одного допустимого черновика и выполните «Проверить состав и порядок набора» — черновик исключён, остальные сохраняют порядок.
2. Верните исключённый черновик положительным номером, назначьте всем выбранным черновикам уникальные места в обратном порядке и повторите действие — восстановление и новый порядок видны в точном пакете.
3. Черновик `BLOCKED` не имеет доступного пути добавления; устаревшая вкладка или существенная правка требуют нового review и аннулируют прежний пакет.
4. В «Проверке и создании» видны состав и порядок, месячный бюджет Strategy, сумма пакета, классификация расхождения, бюджет и период каждого теста, а также все девять областей preflight.
5. Для каждого элемента на карточке кампании понятен Auction Protocol: сравнение, проверяемое изменение, ставки, запросы, автотаргетинг, распределение, бюджет, период, измеряемый результат, условия успеха и остановки.
6. В пользовательской поверхности нет внутренних идентификаторов, подтверждения пакета, внешней записи, показов или расходов.

## Решение владельца

Только владелец #245 может записать `ACCEPTED` или вернуть Feature в новые задачи. До этого артефакт обязан сохранять:

```text
human_checkpoint.verdict = PENDING_HUMAN_VERDICT
implementation_may_claim_acceptance = false
```
