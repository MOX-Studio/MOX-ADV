# Контракт браузерного коллектора Wordstat

**Wayfinder:** [«Зафиксировать контракт сбора Wordstat через headless Playwright»](https://github.com/MOX-Studio/MOX-ADV/issues/319)
**Карта:** [«Спроектировать базовый пайплайн готовой рекламной кампании»](https://github.com/MOX-Studio/MOX-ADV/issues/297)
**Статус:** принятое плановое решение; рабочая реализация относится к `to-spec → to-tickets → /ready`.

## 1. Решение

Канонический источник Wordstat для этапа «Сбор сведений» — авторизованный интерфейс `https://wordstat.yandex.com/`, открываемый только для чтения через headless Playwright.

Авторизация получается из локального Chrome-профиля с отображаемым именем `AI`, но живой профиль никогда не запускается, не подключается по CDP и не передаётся Playwright как `userDataDir`. На каждый запуск создаётся закрытая сессионная копия минимально необходимого состояния. Настоящий Google Chrome открывает только эту копию, после чего в память отдельного непостоянного контекста Playwright переносятся только файлы cookie доменов Яндекса. Браузер-клон закрывается до начала сбора Wordstat, а копия гарантированно удаляется.

Текущий серверный адаптер Wordstat API не является резервным источником. После перехода новый пакет доказательств создаётся либо браузерным коллектором, либо не создаётся. Скрытое переключение на API, объединение API- и UI-строк или продолжение пакета данными другого механизма запрещены.

Wordstat остаётся обязательным доказательством спроса. Только полностью подтверждённый пакет состояния `COMPLETE` выполняет обязательное предусловие этапа. `PARTIAL`, `AUTH_REQUIRED`, `CAPTCHA_OR_CHALLENGE`, `DOM_CHANGED` и `UNAVAILABLE` не означают нулевой спрос и не позволяют сформировать новый Campaign Draft.

## 2. Граница полномочий

Разрешено:

- открыть `wordstat.yandex.com` в изолированном контексте;
- выбрать запрос, вкладку, период, регион и устройство;
- дождаться завершения загрузки;
- прочитать отображённые строки и счётчики;
- использовать официальное действие «Скачать» как канонический способ получения строк, если оно доступно для выбранной вкладки;
- сохранить очищенный типизированный результат и его отпечатки в защищённом хранилище доказательств.

Запрещено:

- подключаться к живой Chrome-сессии или запускать основной каталог `User Data`;
- изменять локальный профиль, входить в аккаунт, вводить пароль, проходить 2FA или CAPTCHA;
- обходить защиту, лимиты, блокировки или проверку безопасности;
- автоматизировать браузерные кабинеты Яндекс Директа или Метрики;
- сохранять значения cookie, содержимое профиля, снимки экрана с аккаунтом, технические данные Keychain или секреты в репозитории, Evidence Snapshot, журнале, Dashboard или ответе агента;
- трактовать Wordstat как CPC, ставку, бюджет, клики, конверсии, пользователей или прогноз эффективности.

## 3. Конфигурация профиля

Продуктовая конфигурация хранит только логическое имя:

```yaml
wordstat_browser:
  profile_name: AI
  browser_channel: chrome
  collector_policy: wordstat-ui-readonly-v1
```

Путь вроде `Profile 4` не является конфигурацией продукта и не попадает в доказательства.

Платформенный адаптер на старте:

1. находит корневой каталог Chrome для текущей ОС;
2. читает только метаданные `Local State`;
3. сопоставляет `profile_name` с `profile.info_cache[*].name` после NFKC-нормализации;
4. требует ровно одно совпадение;
5. возвращает внутренний путь только сессионному менеджеру копии.

Ноль совпадений, несколько совпадений, нечитаемые метаданные или неподдерживаемая платформа дают `UNAVAILABLE` с очищенным кодом причины. Каталог профиля не угадывается по номеру.

## 4. Жизненный цикл сессионной копии

### 4.1. Блокировка

До чтения профиля создаётся атомарная аренда по ключу `Chrome root + profile name`:

- один профиль обслуживает не более одного клона одновременно;
- аренда содержит только `run_id`, PID и срок;
- другой запуск ожидает не более 30 секунд и затем получает `UNAVAILABLE/PROFILE_CLONE_BUSY`;
- устаревшая аренда снимается только после проверки отсутствия её процесса и уборки её каталога;
- клон и cookies одной Pi-сессии никогда не используются другой сессией.

Сбор запросов внутри одного пакета всегда последовательный.

### 4.2. Снимок

Сессионный каталог создаётся вне репозитория в приватном runtime/temp-каталоге с правами `0700` и случайным именем. Копируется allowlist:

- корневой `Local State`;
- `Preferences` выбранного профиля;
- семейство базы cookie выбранного профиля: актуальный `Network/Cookies` либо legacy `Cookies`, а также существующие рядом `-journal`, `-wal` и `-shm` файлы.

Не копируются History, Login Data, Web Data, расширения, Local/Session Storage, кэш, загрузки, закладки и другие данные профиля. Расширение allowlist требует отдельного решения безопасности; автоматического перехода к полной копии профиля нет.

Если исходный Chrome меняет SQLite-файлы во время копирования, сессионный менеджер проверяет согласованность копии. Одна повторная попытка создать снимок допустима после короткой задержки; запуск исходного профиля не останавливается и исходные файлы не блокируются на запись. Повторная несогласованность даёт `UNAVAILABLE/PROFILE_SNAPSHOT_INCONSISTENT`.

### 4.3. Извлечение сессии

Клон запускается через `launchPersistentContext` настоящего Google Chrome в headless-режиме. `userDataDir` указывает только на сессионный каталог. Имя фактического подкаталога передаёт платформенный адаптер.

На macOS обязательна проверенная настройка:

```ts
ignoreDefaultArgs: ["--use-mock-keychain", "--password-store=basic"]
```

Она применяется только к клону: основной профиль не автоматизируется. Остальные стандартные защитные аргументы Playwright не отключаются.

После открытия Wordstat клон должен одновременно подтвердить:

- итоговый host принадлежит Wordstat, а не Passport;
- отсутствует форма входа, 2FA, CAPTCHA или challenge;
- присутствуют авторизованный признак «Выйти», поле запроса и вкладки результатов.

Затем:

1. из persistent context читаются cookies;
2. в памяти остаются только cookies с доменами `yandex.ru`, `.yandex.ru`, `yandex.com` и `.yandex.com`;
3. они добавляются в новый непостоянный `BrowserContext` того же запуска;
4. массив со значениями cookie очищается из памяти;
5. persistent context закрывается;
6. процесс Chrome-клона должен завершиться до первого поискового запроса в изолированном контексте;
7. авторизация повторно проверяется уже в изолированном контексте.

Файл `storageState`, HAR, trace, видео и снимки экрана для этого шага не создаются.

### 4.4. Завершение и уборка

Уборка выполняется при успехе, отказе, тайм-ауте, отмене и исключении:

1. остановить выдачу новых действий;
2. закрыть непостоянный контекст;
3. закрыть persistent context, если он ещё открыт;
4. дождаться завершения группы процессов, затем применить ограниченный `TERM → KILL` только к процессам клона;
5. удалить каталог загрузок и сессионный профиль;
6. убедиться, что каталог отсутствует и процессов клона не осталось;
7. снять аренду последней.

`COMPLETE` допустим только после успешной уборки. Если строки собраны, но процесс или каталог удалить не удалось, результат не принимается: `UNAVAILABLE/CLEANUP_FAILED`, каталог помещается в приватный карантин для повторной уборки без раскрытия пути человеку.

## 5. Детерминированный план сбора

Один `WordstatCollectionPlan` фиксируется до открытия браузера и входит в `plan_digest`:

```yaml
schema_version: wordstat-ui-collection-plan-v1
seeds:
  - seed_id
    exact_query
    operator_profile
scope:
  regions: [{provider_id, label}]
  device: ALL | DESKTOP | SMARTPHONE | TABLET
  dynamics:
    granularity: MONTH
    from_date
    to_date
surfaces:
  - TOP_POPULAR
  - TOP_SIMILAR
  - DYNAMICS
  - REGIONS
limits:
  maximum_seeds: 8
  parallel_queries: 1
```

Запрос хранится точно, включая операторы. Нормализованная копия используется только для сравнения и отпечатка; она не заменяет фактически отправленный запрос.

Для каждой формулировки коллектор выполняет один и тот же порядок:

1. открыть «Топы запросов»;
2. выставить точный регион и устройство, затем подтвердить выбранные подписи в UI;
3. отправить `exact_query`;
4. получить раздельные результаты «Популярные» и «Похожие» за заявленный интерфейсом последний месяц;
5. открыть «Динамика», выставить тот же регион и устройство, детализацию по месяцам и точный диапазон дат;
6. открыть «Регионы», выставить устройство и получить распределение за заявленные интерфейсом последние 30 дней;
7. вернуть фильтры к каноническому состоянию перед следующей формулировкой.

Результаты разных вкладок и областей не складываются. «Похожие» не подменяют «Популярные», индекс интереса не подменяет число запросов, а несколько устройств или регионов не суммируются без отдельного совпадающего правила агрегации.

### Подтверждение завершённой загрузки

Поверхность считается загруженной только когда:

- исчез индикатор загрузки;
- UI показывает ожидаемый запрос и все выбранные фильтры;
- присутствует таблица либо явное штатное состояние отсутствия строк;
- заголовки соответствуют версии parser contract;
- количество строк и видимые счётчики не меняются в двух последовательных проверках;
- числовые поля разбираются без догадок;
- официальный CSV, когда он предусмотрен вкладкой, успешно скачан и прошёл проверку заголовков.

CSV является каноническим набором строк; DOM подтверждает запрос, область, состояние и контрольные значения. Если кнопка «Скачать» или структура CSV изменилась, DOM не используется как скрытый резервный канал для статуса `COMPLETE`.

Явное штатное состояние с нулём строк даёт завершённое наблюдение `NO_ROWS_RETURNED`. Его семантика: «Wordstat не вернул строк в этой точной области и момент наблюдения», а не «спрос равен нулю».

## 6. Пакет доказательств

Новая схема:

```yaml
schema_version: wordstat-ui-observation-batch-v1
source: YANDEX_WORDSTAT_UI
transport: HEADLESS_PLAYWRIGHT
collector_version
ui_parser_version
batch_id
run_id
plan_digest
batch_started_at
batch_finished_at
status: COMPLETE | PARTIAL | AUTH_REQUIRED | CAPTCHA_OR_CHALLENGE | DOM_CHANGED | UNAVAILABLE
observations:
  - observation_id
    seed_id
    exact_query
    normalized_query
    operator_profile
    surface: TOP_POPULAR | TOP_SIMILAR | DYNAMICS | REGIONS
    observed_at
    scope:
      provider_region_ids
      region_labels
      device
      declared_window
      from_date
      to_date
      granularity
    rows
    displayed_row_count
    explicit_empty_state
    request_fingerprint
    response_fingerprint
    parser_contract
    limitations
failures:
  - code
    affected_seed_ids
    affected_surfaces
    attempt
    retry_after_seconds
cleanup_status: COMPLETE | FAILED
```

Типы строк:

- `TOP_POPULAR` и `TOP_SIMILAR`: `rank`, `phrase`, `count`;
- `DYNAMICS`: `period_start`, `count`, `share`;
- `REGIONS`: `provider_region_id`, `region_label`, `count`, `share`, `affinity_index`.

В защищённом сыром артефакте сохраняются очищенный CSV, parser version и digest. В `Analytics Evidence Snapshot` попадают нормализованные строки, точная область, время, provenance, ограничения и ссылки на защищённый артефакт. HTML, cookies и данные профиля не входят ни в один пакет.

`TOP_POPULAR` сохраняет принятую семантику `LOWER_BOUND_OBSERVED_TOP_ROWS`. Отсутствующая seed-строка остаётся `UNKNOWN`, а не `0`. `TOP_SIMILAR` является отдельным наблюдением для расширения семантики и не увеличивает частотность seed. Wordstat не может сформировать денежный `CostObservation`.

## 7. Состояния и точные действия

| Состояние | Условие | Повтор | Результат этапа |
|---|---|---|---|
| `COMPLETE` | Все запланированные поверхности подтверждены, отпечатки рассчитаны, clone закрыт и удалён | Не нужен | Пакет может войти в новый Analytics Evidence Snapshot |
| `PARTIAL` | Хотя бы одна поверхность подтверждена, но другая не завершилась или дала неоднозначный частичный результат | Только затронутая единица, в пределах политики | Сохраняется как неполное evidence; обязательный Wordstat gate не пройден |
| `AUTH_REQUIRED` | Redirect на Passport, форма входа, истёкшая сессия, 2FA или перенос cookies не подтвердил авторизацию | Автоматического повтора нет | Точный запрос: войти в Wordstat в локальном профиле `AI`, затем запустить новый run |
| `CAPTCHA_OR_CHALLENGE` | CAPTCHA, security challenge, ограничение подозрительной нагрузки | Автоматического обхода и повтора нет | Точный запрос: разрешить challenge вручную вне пайплайна либо дождаться восстановления доступа |
| `DOM_CHANGED` | Контрольные роли, вкладки, заголовки, CSV или инварианты parser contract изменились | Одна перезагрузка допустима только до классификации; затем нет | Не использовать строки; требуется обновление адаптера и fixture contract |
| `UNAVAILABLE` | Профиль/платформа/клон/Chrome/сеть/блокировка/уборка недоступны либо ни одна поверхность не подтверждена | Только временные причины | Wordstat недоступен; спрос не равен нулю; новый Draft не формируется |

Дополнительные `failure.code` уточняют состояние: `PROFILE_NOT_FOUND`, `PROFILE_AMBIGUOUS`, `PROFILE_CLONE_BUSY`, `PROFILE_SNAPSHOT_INCONSISTENT`, `BROWSER_LAUNCH_FAILED`, `AUTH_COOKIE_TRANSFER_FAILED`, `TRANSIENT_NETWORK`, `LOAD_TIMEOUT`, `EXPLICIT_ACCESS_BLOCK`, `CSV_SCHEMA_CHANGED`, `TABLE_INCOMPLETE`, `CLEANUP_FAILED`.

## 8. Политика повторов и нагрузки

- Один seed выполняется за раз; параллельных вкладок сбора нет.
- Между действиями, вызывающими новое чтение Wordstat, выдерживается не менее 3 секунд.
- Для `TRANSIENT_NETWORK`, `LOAD_TIMEOUT` и `TABLE_INCOMPLETE` допустимы начальная попытка и не более двух повторов: через 10 и 30 секунд.
- Повторяется только затронутая поверхность текущего seed.
- `AUTH_REQUIRED`, `CAPTCHA_OR_CHALLENGE`, `DOM_CHANGED`, `EXPLICIT_ACCESS_BLOCK` и любая ошибка уборки завершают пакет без повторов.
- При появлении auth/challenge сбор следующих seed прекращается.
- Новый продуктовый запуск всегда создаёт новый batch; он не дополняет старый `PARTIAL` и не объединяет его со старым API-пакетом.

## 9. Миграция существующего контура

Одномоментный cutover заменяет создание новых API-пакетов:

| Сейчас | После cutover |
|---|---|
| `YANDEX_WORDSTAT_V1` | `YANDEX_WORDSTAT_UI` |
| `wordstat_api` | `wordstat_ui` |
| `WORDSTAT_OFFICIAL_API` | `WORDSTAT_AUTHORIZED_UI` |
| `api.wordstat.yandex.net` | `wordstat.yandex.com` |
| `api_parser` | `playwright_ui_csv_parser` |
| OAuth token + client ID | локальное логическое имя Chrome-профиля |
| `/v1/topRequests`, `/v1/dynamics`, `/v1/regions` | `TOP_POPULAR`, `TOP_SIMILAR`, `DYNAMICS`, `REGIONS` |

Необходимо удалить из активного исполнения:

- чтение `YANDEX_WORDSTAT_OAUTH_TOKEN` и `YANDEX_WORDSTAT_CLIENT_ID`;
- preflight `/v1/getRegionsTree`;
- вызов `collectOfficialWordstatBatch` как production-механизма;
- тексты UI «официальное API» и policy `browser_cabinet_allowed: false` применительно к Wordstat.

Исторические API-backed Evidence Snapshot остаются неизменяемыми и проверяемыми со старой схемой. Они получают только legacy-классификацию при чтении. Новые Snapshot не переписывают и не смешивают старые строки.

Нормализатор v2 может сохранить полезные текущие поля — `seed_id`, `cluster_id`, точную фразу, регион, устройство, время, rows и fingerprints — но provenance, source kind, окна, surface и parser version меняются честно. Более позднее решение владельца в этом документе отменяет только API-транспорт раннего `docs/research/analytics-evidence-contract.md`; семантические ограничения Wordstat и запрет денежной интерпретации сохраняются.

## 10. Прозрачность

Компактный пользовательский блок показывает:

- источник: «Яндекс Wordstat»;
- область: подписи регионов, устройство, период и число проверенных формулировок;
- свежесть: время наблюдения и действующая freshness policy;
- состояние: получено полностью, частично или недоступно;
- ограничение: частотность не является CPC, бюджетом, кликами, конверсиями или прогнозом результата;
- одно точное действие человека только для `AUTH_REQUIRED` или `CAPTCHA_OR_CHALLENGE`.

Не показываются профильный путь, имя каталога, cookie, email аккаунта, Keychain, PID, temp-path, DOM-селекторы, stack trace и provider IDs. Очищенный системный след хранит `run_id`, версии адаптера и parser contract, `plan_digest`, статусы попыток, коды отказов, evidence refs и факт успешной уборки.

## 11. Тестовые швы

### CI/E2E без авторизации

Контролируемая локальная fixture-страница воспроизводит тот же accessibility/CSV contract и сценарии:

- полный результат всех четырёх поверхностей;
- явная пустая выдача;
- медленная и частично загруженная таблица;
- исчезнувшая вкладка или изменённый CSV;
- redirect/login, CAPTCHA/challenge и access block;
- отмена во время загрузки;
- конфликт аренды и ошибка уборки.

Production-сборщик может получить fixture base URL только через compile-time/test dependency injection. Такой пакет имеет `source: TEST_FIXTURE`, не проходит production Evidence Snapshot Builder и не может выполнить обязательный Wordstat gate.

### Локальная авторизованная дымовая проверка

Отдельная ручная команда:

1. разрешает профиль по имени `AI`;
2. создаёт сессионный клон;
3. переносит только Yandex cookies;
4. закрывает клон;
5. выполняет запрос `виброизоляция`;
6. подтверждает авторизацию, `TOP_POPULAR`, заполненную таблицу и действие «Скачать»;
7. закрывает контекст, удаляет загрузки и клон;
8. выводит только состояние, число строк, версии collector/parser и факт уборки.

Она не создаёт Analytics Evidence Snapshot, не печатает строки запроса кроме известного smoke seed, не сохраняет cookies, `storageState`, CSV, HTML, trace, видео или скриншот.

## 12. Сценарии приёмки

1. Профиль находится по имени, даже если его каталог переименован; `Profile 4` нигде не зафиксирован в продуктовой логике.
2. Открытая пользовательская Chrome-сессия не подключается и не изменяется; до/после smoke совпадают контрольные метаданные исходных файлов.
3. Клон успешно переносит авторизацию, закрывается до первого запроса и удаляется после результата.
4. Истёкшая сессия даёт `AUTH_REQUIRED`; пароль, 2FA и CAPTCHA не вводятся автоматически.
5. CAPTCHA или challenge немедленно прекращают пакет и не вызывают повторов.
6. Изменение fixture DOM/CSV даёт `DOM_CHANGED`, а не пустые строки или API-fallback.
7. Частично загруженная таблица после повторов даёт `PARTIAL`; пробел не становится нулём.
8. Явная штатная пустая выдача даёт `COMPLETE/NO_ROWS_RETURNED`, но не claim о нулевом спросе.
9. Два запуска не используют один clone; второй ограниченно ждёт либо получает `PROFILE_CLONE_BUSY`.
10. Stop, timeout, exception и принудительное завершение не оставляют процесс, download или session clone.
11. Новый Evidence Snapshot содержит только `YANDEX_WORDSTAT_UI`; смешанный UI+API batch отклоняется схемой.
12. Dashboard показывает источник, область, свежесть, состояние и ограничения без профиля, cookies, Keychain и provider IDs.
13. Репозиторий, журналы и ответы не содержат cookie values, содержимое профиля или авторизационные артефакты.
14. Wordstat-наблюдение не может создать денежный cost candidate.
